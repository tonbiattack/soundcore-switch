# Soundcore Switch — 仕様書

最終更新: 2026-11-17

> このドキュメントは**要件の正**である。何を作るか・何を作らないかを定義する。
> 実装状況は §10〜§12 に反映する。プロトコルの詳細は [RESEARCH.md](./RESEARCH.md)、
> 機種対応は [SUPPORT_MATRIX.md](./SUPPORT_MATRIX.md) を参照。

## 1. 目的
Soundcore純正アプリでマルチポイント接続先を切り替える際の「起動→イヤホン読込→設定画面→接続先変更」という待ち時間と操作数を減らす、Android向けの単機能アプリ。

## 2. スコープ
- **対象**: Soundcore製のマルチポイント対応イヤホン。まず所有機種（Space A40およびもう1機種。正確な型番は実機確認）を検証対象とする。
- **主機能**: 接続状態の表示、接続先候補の表示、接続先の切り替え要求と結果確認。
- **対象外**: ノイズキャンセリング、イコライザー、ファームウェア更新、音楽再生、アカウント管理。
- まず個人利用前提。追加メーカー対応はMVP対象外。

## 3. ユーザーストーリー
1. アプリを開くとすぐに利用可能なイヤホンと現在の接続先が分かる。
2. PC・スマホ・タブレット等の候補をタップすると、可能な範囲で接続先を切り替えられる。
3. 失敗した場合は理由と対処方法が表示され、無駄な再読み込みを強制しない。

## 4. MVP機能要件
| ID | 優先度 | 要件 | 受け入れ条件 |
|---|---|---|---|
| F-01 | Must | 対応イヤホン選択 | 検出済み・登録済みのイヤホンを表示し、機種別の対応状況を分かるようにする |
| F-02 | Must | 接続状態表示 | 取得可能な接続状態を明確に表示し、取得不可は「不明」とする |
| F-03 | Must | 接続先候補表示 | 独自プロトコルで取得できる場合のみ候補一覧を表示。Android側で見える端末一覧をイヤホンの登録済み一覧と混同しない |
| F-04 | Must | ワンタップ切り替え | 技術検証で実現可能と判定した機種のみ有効化。切り替え完了を状態再取得などで確認する |
| F-05 | Must | 失敗・権限処理 | Bluetoothオフ、権限不足、イヤホン未接続、タイムアウト、非対応を区別して通知する |
| F-06 | Should | 高速起動 | 初期画面はローカルキャッシュから即描画し、状態更新を非同期に実行する |
| F-07 | Should | 最終利用イヤホン記憶 | 前回選択機種を復元する |
| F-08 | Could | ホーム画面ショートカット | 対応が確認された接続先へのショートカットを提供する |

## 5. UX原則
- 「起動→接続先を選ぶ→完了」を理想の操作経路とする。
- 画面遷移・ローディング・確認ダイアログを最小化。
- キャッシュした接続先は古い可能性を明示。キャッシュ表示と実際の接続完了を混同しない。
- 切り替え処理の二重送信防止。タイムアウト時は安全に再試行可能にする。
- 複数のSoundcoreイヤホンを切り替えて使える設計にする。

## 6. 技術方針と制約
- Androidネイティブを第一候補（Kotlin / Jetpack Compose）。
- Bluetooth権限はAndroidバージョン別に最小限で要求する。
- Android標準Bluetooth APIで分かる接続状態と、Soundcoreイヤホン内部の**マルチポイント登録端末リスト・切り替え操作は別物**。
- 純正アプリの内部API・BLE/GATT等の通信調査が必要な場合がある。通信経路、認証、暗号化、互換性、利用条件を検証する。
- **他端末（PCなど）のBluetooth接続をAndroidから任意に操作できることは保証されない**。デバイス側プロトコルで実現できなければ、MVPを「状態表示＋可能な範囲の接続補助」に縮小する。
- root、アクセシビリティでの純正アプリ自動タップ、非公開OS APIへの依存は原則回避。
- 端末識別子・ペアリング情報を外部送信しない。通信ログには秘密情報を記録しない。

## 7. 技術検証の合格基準（実装前のゲート）
1. 実機の正確な機種名・ファームウェア・Androidバージョンを記録。
2. 純正アプリでの切り替え手順と、切り替え前後の接続状態を記録。
3. 権限・通信手段・取得できる接続先情報・切り替えコマンドの可否を検証。
4. 「Android本体が接続先でないとき」「2台接続中」「片方切断中」などで挙動を確認。
5. 切り替え成功・失敗をアプリから正しく判別できることを確認。
6. 機種ごとに **supported / partial / unsupported / unknown** を記録。

## 8. 非機能要件
- 起動時はブロッキング通信なしでUI表示。体感速度を優先。
- 権限不足でクラッシュしない。バックグラウンド常駐をMVP必須としない。
- 機種ごとの差異をアダプタ層で隔離し、テスト可能にする。
- 外部サーバー・ログイン不要、オフライン利用前提。

## 12. 仕様からの変更点

実装中に判明した事実により、当初の想定を変更した点を記録する。

| 項目 | 当初 | 変更後 | 理由 |
|---|---|---|---|
| 切り替えの実現可否 | 実現できなければ「状態表示＋接続補助」に縮小 | **実現した** | 機種固有プロトコルを解読できたため |
| 対象プラットフォーム | Android のみ | **Android + Windows** | 同じプロトコルが Windows からも使えたため |
| 接続状態の取得 | Android 標準 API で取得 | 端末により取得不可。「不明」と表示 | OPPO ではプロファイル API が使えない |
| 切り替えの成否判定 | コマンドの応答で判定 | **状態の再取得で判定** | 応答と実効果が一致しないことを実機で確認 |

詳細は [RESEARCH.md](./RESEARCH.md) と [VERIFICATION_A40.md](./VERIFICATION_A40.md) を参照。
