# Android 実機検証レポート — OPPO CPH2699

実施日: 2026-11-17
対象: OPPO CPH2699（Android 16 / API 36 / ColorOS）
イヤホン: soundcore Liberty 4 NC (A3947)

> このドキュメントは **Android 実機での検証記録**である。
> 検証で見つけて直した不具合と、その再現条件を残す。
> プロトコルの仕様は [RESEARCH.md](./RESEARCH.md)、
> Space A40 固有の知見は [VERIFICATION_A40.md](./VERIFICATION_A40.md) を参照。

## 1. 結論

**Android 実機で接続先一覧の取得と切り替えに成功した。** ただし実機検証で
3件の実装バグを発見し、修正した。いずれもエミュレータでは再現しない、
実機固有の挙動に起因する。

| 項目 | 結果 |
|---|---|
| アプリ起動・画面表示 | ✅ 正常（クラッシュなし） |
| 権限要求フロー | ✅ 正常 |
| イヤホン検出 | ✅ 5台の Soundcore 製品を検出 |
| 接続先一覧の取得 | ✅ 7台の登録端末と接続状態を取得 |
| 接続先の切り替え | ✅ 成功（DELLTOWER へ切り替え） |
| 失敗時の表示 | ✅ 成功と偽装しない |

## 3. 発見した不具合と修正

### 3.1 接続状態の誤判定（重要度: 高）

**症状**: イヤホンが A2DP で接続中なのに「切断中」と表示され、切り替えが無効化された。

**原因**: OPPO は A2DP / HEADSET のプロファイル API をアプリに公開していない。

```
profile=2 (A2DP)    取得失敗 IllegalArgumentException
profile=1 (HEADSET) 取得失敗 IllegalArgumentException
profile=7 (GATT)    接続中=1 件 → Garmin 時計のみ
```

`getConnectedDevices()` が `IllegalArgumentException`、`getConnectionState()` が
`null` を返す。GATT だけが応答するが、GATT は BLE の別経路であり
**音声接続の有無を表さない**。実際、接続中のイヤホンに対して
`STATE_DISCONNECTED` を返していた。

**修正**: クラシック音声プロファイル（A2DP / HEADSET）のいずれかを確認できた
場合に限り「判定完了」とみなすようにした。GATT しか確認できない場合は
`UNKNOWN`（不明）とし、切断と断定しない（仕様書 F-02）。

### 3.2 「不明」を理由に切り替えを塞いでいた（重要度: 高）

**症状**: 3.1 の結果、接続状態が `UNKNOWN` になり、切り替えが永久に無効化された。

**原因**: `canSwitch` と `SwitchTargetUseCase` が「接続中（CONNECTED）」を
要求していた。`UNKNOWN` は「取得できなかった」だけで切断ではない。

**修正**: 「切断中と確定している」場合だけ止めるようにした。`UNKNOWN` は
操作を許可し、実際に到達できなければ通信が失敗して具体的な理由で伝わる。

### 3.3 操作元の端末を切断対象に選んでいた（重要度: 高）

**症状**: 接続上限（2台）に達したとき、切断対象として**操作元の OPPO 自身**が
選ばれ、通信が途切れて切り替えが成立しなかった。

**原因**: 切断対象の判定を名前のキーワード（"pc" / "desktop"）で行っていた。
OPPO の Bluetooth 名「OPPO Reno13 A」はどれにも該当しないため、
先頭要素（＝OPPO 自身）が選ばれていた。

**修正**: 操作元の Bluetooth 名を `BluetoothAdapter.getName()` から取得し、
一覧の表示名と照合して除外するようにした。

```
修正後ログ: 切断対象=DELLTOWER 操作元名=OPPO Reno13 A 接続中=[OPPO Reno13 A, DELLTOWER]
```

### 3.4 切り替え結果の表示が画面外に出ていた（重要度: 中）

**症状**: 切り替えは実行されるが、結果バナーが表示されなかった。

**原因**: 結果バナーを `LazyColumn` の後に置いていたため、一覧が高さを占有して
画面外に押し出されていた。

**修正**: 結果バナーを一覧より上に移動した。

### 3.5 応答の待ち時間が短すぎた（重要度: 中）

**症状**: 切断・接続コマンドの応答を取りこぼし、コマンドが届いたか確認できなかった。

**原因**: 応答を待たないコマンドの受信猶予が 500ms だった。イヤホンが
処理を終えるまでに時間がかかる。

**修正**: 猶予を 1.5 秒に延長した。これで応答が取れるようになった。

```
応答 cmd=0B81 body=[90 FB C5 9D 28 F4]   ← 切断コマンドに DELLTOWER の MAC が返る
```

### 3.6 切り替え完了の確認が1回だけだった（重要度: 中）

**症状**: 実際には切り替わっているのに「確認できませんでした」と表示されることがあった。

**原因**: 接続コマンド送信直後に1回だけ状態を確認していた。イヤホンが接続を
確立するまで数秒かかるため、反映前の状態を見て失敗と判定していた。

**修正**: 1.5 秒間隔で最大4回確認するようにした。

### 3.7 イヤホン名が見切れていた（重要度: 中）

**症状**: イヤホン選択チップが横並びで、名前が長い機種が「soundcore Libert...」と
省略され、どの機種か判別できなかった。同名の Liberty 4 NC を2台ペアリングして
いる場合、区別がまったくできなかった。

**原因**: `Row` に `FilterChip` を横並びで置き、`maxLines = 1` +
`TextOverflow.Ellipsis` で省略していた。

**修正**: 1台1行の縦並びに変更し、名前を折り返して最後まで表示するようにした。
あわせて、選択中の1台だけ常に表示し、残りは「他のイヤホンを表示（N台）」で
折りたたむようにした。台数が多いと接続先の一覧が押し下げられるため。

### 3.8 切断の成否を確認していなかった（重要度: 高）

**症状**: 切断が拒否されてもそのまま接続コマンドを送っており、接続上限が
空かないため切り替えが必ず失敗していた。

**原因**: 切断コマンドの成否を確認していなかった。

**修正**: 切断後に一覧を再取得して実際に切断されたかを確認し、拒否された場合は
次の候補を試すようにした。1台も切断できなければ接続コマンドを送らずに失敗を返す。
詳細は [VERIFICATION_A40.md](./VERIFICATION_A40.md) を参照。

## 4. 動作確認の記録

### 4.1 接続先一覧の取得

```
接続中: OPPO Reno13 A
接続中: DELLTOWER
切断中: DESKTOP-ILQVMVD
切断中: CXDEPC26100444
切断中: Redmi Pad SE 8.7
切断中: MPC144
切断中: REDPINE_GATT_V02
```

### 4.2 切り替え成功

DELLTOWER をタップ → 「DELLTOWER に切り替えました」と表示され、
一覧でも DELLTOWER が接続中になった。

### 4.3 失敗時の挙動

Bluetooth 圏外の DESKTOP-ILQVMVD をタップした場合、
「切り替えを確認できませんでした」と表示された。**成功と偽装しない**
（仕様書 F-04）。

## 5. 重要な運用上の注意

### 5.1 純正アプリが RFCOMM チャネルを占有する

**Soundcore 純正アプリ（`com.oceanwing.soundcore`）がバックグラウンドで動いていると、
RFCOMM 接続が失敗する。** 実測では、純正アプリのプロセスが同じチャネル（15）を
保持しており、本アプリの接続が即座に閉じられていた。

```
BluetoothSocket: connect(), SocketState: INIT
BluetoothSocket: close() ... mSocketState: INIT   ← 接続できずに閉じている
```

純正アプリを `am force-stop` すると接続できるようになった。

**対処**: 本アプリの利用時は純正アプリを終了しておく必要がある。
将来的には、接続失敗時にその旨を案内する改善が望ましい。

### 5.2 同名デバイスが複数ある場合

Liberty 4 NC を2台ペアリングしている場合、一覧に同名で2件表示される。
どちらが接続中かは接続状態ドットで判別できるが、名前だけでは区別できない。
接続中の方を選ぶ必要がある。
