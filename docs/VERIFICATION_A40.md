# Space A40 実機検証レポート

実施日: 2026-11-17
対象: Soundcore Space A40 (A3936) / Windows 11 + MediaTek Bluetooth Adapter
検証方法: プロトコルを直接叩き、イヤホンの応答と実際の状態変化を独立に確認

## 1. 結論

**A40 でも接続先一覧の取得と切り替えコマンドは動作する。** ただし
**コマンドの応答有無だけでは成否を判定できない**ことが判明した。
これはアプリの実装方針に関わる重要な発見である。

| 項目 | 結果 |
|---|---|
| 接続先一覧の取得 | ✅ 7台の登録端末と接続状態を取得 |
| マルチポイント有効状態の取得 | ✅ 有効（フラグ=1） |
| 切断コマンド | ⚠️ 対象により成否が分かれる |
| 接続コマンド | ✅ 動作する（応答が返らない場合もある） |

## 2. コマンドごとの応答

| コマンド | 応答 | 実際の効果 |
|---|---|---|
| `0B 01` 一覧取得 | ✅ あり | 7台を返す |
| `01 01` 状態取得 | ⚠️ 不安定（応答なしのことも） | — |
| `0B 84` マルチポイント有効化 | ✅ あり（現在値 `01`） | — |
| `0B 81` 切断 | ⚠️ 対象次第 | 対象次第 |
| `0B 82` 接続 | ⚠️ 不安定 | **動作する** |

## 3. 重要な発見: 応答だけでは成否を判定できない

### 3.1 切断が成功した例

OPPO Reno13 A (`7A:A7:6A:03:DD:08`) を切断:

```
送信: 08 EE 00 00 00 0B 81 10 00 7A A7 6A 03 DD 08 18
応答: 09 FF 00 00 01 0B 81 10 00 7A A7 6A 03 DD 08 18
      （続けて更新後の一覧が返る）
結果: 接続中 2台 → 1台（OPPO が切断された）
```

### 3.2 切断が失敗した例

DELLTOWER (`90:FB:C5:9D:28:F4`) を切断:

```
送信: 08 EE 00 00 00 0B 81 10 00 90 FB C5 9D 28 F4 9B
応答: なし
結果: 接続中 2台のまま（DELLTOWER は切断されない）
```

**同じコマンドでも対象によって結果が異なる。** DELLTOWER は Windows PC であり、
その PC が接続を維持しているため、イヤホン側からの切断要求が拒否されると考えられる。

### 3.3 接続が成功した例（応答なし）

DESKTOP-ILQVMVD (`00:B3:2C:83:80:D8`) へ接続:

```
送信: 08 EE 00 00 00 0B 82 10 00 00 B3 2C 83 80 D8 4D
応答: なし
結果: 接続中になった（状態が変化した）
```

**応答が返らなくても実際には接続される。** 応答の有無で成否を判断してはならない。

## 4. 接続上限の挙動

接続上限は2台。上限に達している状態で3台目へ接続コマンドを送っても、
**接続されない**（応答は返ることがある）。

```
接続中: DESKTOP-ILQVMVD, DELLTOWER（2台）
→ Nintendo Switch へ接続コマンド送信 → 応答あり
→ 状態: 変化なし（上限のため）
```

したがって切り替えには「先に1台切断する」処理が必須である。
ただし 3.2 のとおり、切断が拒否される場合がある。

## 5. アプリ実装への影響

### 5.1 現在の実装の問題

`SoundcoreMultipointAdapter` は接続コマンド送信後に状態を再取得し、
対象が `connected` になったかを確認している。この方針自体は正しい。

ただし、**切断コマンドの成否を確認していない**。切断が拒否された場合でも
そのまま接続コマンドを送ってしまい、上限に達したままなので失敗する。

### 5.2 改善案

1. 切断コマンド送信後、**一覧を再取得して実際に切断されたか確認する**。
2. 切断できていなければ、別の端末を切断対象にする、または失敗として返す。
3. 接続コマンドの応答有無ではなく、**状態の再取得結果だけで成否を判定する**
   （現状の実装はこれに沿っている）。

## 6. 未確認点

- DELLTOWER の切断が拒否される理由の特定（PC 側の接続維持が原因と推測）
- A40 の `dualEnabledOffset`（状態 body のどこに有効フラグがあるか）
- 切断拒否時に別の端末を選び直せば成功するか
- Liberty 4 NC でも同様の「応答なしで成功」が起きるか

## 7. 検証に使ったスクリプト

`scripts/probe-soundcore.ps1` に、プロトコルを直接叩いて
イヤホンの応答と Windows 側の接続状態を並べて表示するスクリプトを置いた。
実機検証の再現に使える。
