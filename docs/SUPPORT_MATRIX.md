## 対応レベルの定義

仕様書 §7-6 の4区分。アプリ内の `SupportLevel` と1対1で対応する。

| レベル | 意味 | アプリの挙動 |
|---|---|---|
| `supported` | 接続先の取得と切り替えの両方を実機で確認済み | 切り替え操作を有効化 |
| `partial` | 接続状態の表示のみ実機で確認済み | 表示のみ。切り替えは無効 |
| `unsupported` | 対象外と確認済み | 表示のみ。切り替えは無効 |
| `unknown` | 未検証 | 表示のみ。切り替えは無効 |

**`supported` 以外では切り替え操作を出さない。** これは「切り替えたつもりで
切り替わっていない」という最悪の誤動作を防ぐための、意図的な制約である。

### Liberty 4 NC の検証内容（2026-11-17）

**Windows 11 + MediaTek Bluetooth Adapter**（A2DP 接続）:
ベンダー UUID `0cf12d31-fac3-4553-bd80-d6832e7b3947` に RFCOMM 接続して確認。

- 接続先一覧の取得: **成功**。7台の登録端末と接続状態を取得。
- 切り替えコマンド (`0B 82` + MAC) の送信: **成功**（応答あり）。
- 完了検出: **成功**。一覧を再取得して `connected` フラグで判定。

**OPPO CPH2699（Android 16 / API 36）**:

- 接続先一覧の取得: **成功**。7台の登録端末と接続状態を取得。
- 切り替え: **成功**（DELLTOWER へ切り替え、「切り替えました」と表示）。
- 失敗時の挙動: **成功と偽装しない**（圏外の端末を指定すると「確認できませんでした」）。

詳細は [VERIFICATION_ANDROID.md](./VERIFICATION_ANDROID.md) を参照。

### 既知の制約

- **Soundcore 純正アプリが起動していると RFCOMM 接続に失敗する。**
  純正アプリが同じチャネルを占有するため。利用時は純正アプリを終了しておく必要がある。
- 同時接続は2台まで。上限時は先に1台切断する（アプリが自動で行う）。
- 端末によっては A2DP / HEADSET のプロファイル API が使えない
  （OPPO CPH2699 で確認）。その場合、イヤホンの接続状態は「不明」と表示されるが、
  切り替え操作は可能（実際の到達可否は通信結果で判断する）。

## この表の更新方法

この表は**アプリのコードと一致していなければならない**。
唯一の正は `core/src/main/kotlin/com/tonbiattack/soundcoreswitch/domain/model/ModelCatalog.kt` の
`supportLevels` マップである。

機種を `supported` に昇格させる手順:

1. 仕様書 §7 の合格基準をすべて満たす検証を行う。
2. `ModelCatalog.kt` の `supportLevels` を更新する。
3. `ModelCatalog.kt` の `KNOWN_MODELS` に機種を追加する（未登録なら）。
4. `SoundcoreUuids.modelCodeOf()` に機種コードを追加する。
5. この表を更新する。
6. `docs/RESEARCH.md` に検証結果と再現手順を追記する。

**2 と 4 を同時に行うこと。** 機種コードが無いとアダプタが UUID を組み立てられず、
切り替えボタンは出るが必ず失敗する状態になる。

## 制限事項

- **Android 標準 API だけでは、イヤホン内部の接続先一覧も切り替えも取得できない。**
  機種固有の RFCOMM プロトコルを使う。詳細は [RESEARCH.md](./RESEARCH.md) を参照。
- 同時接続は機種の上限（Liberty 4 NC は2台）に従う。上限に達している場合、
  アプリは自動的に1台を切断してから接続する。
- 「この端末自身」がどれかはプロトコルから分からない。切断対象の選択は
  表示名からの推定に頼るため、名前を変更していると意図しない端末を切る可能性がある。
- 接続状態が取得できない場合は「不明」と表示する。切断中とは区別する。
- 他端末（PC 等）の Bluetooth 接続を任意に操作できることは保証されない
  （仕様書 §6）。本アプリはイヤホン側のプロトコル経由でのみ操作する。
